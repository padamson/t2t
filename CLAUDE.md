# Trunk to Table — Book Project

This is the manuscript repo for *Trunk to Table: Building a Full-Stack Rust Application with Agentic Continuous Delivery*. The book and CuisineIQ are open source.

## Repo structure

- `book.toml` — mdbook configuration (HTML + typst-pdf backends)
- `template.typ` — Custom Typst template for print-quality PDF
- `src/SUMMARY.md` — Table of contents
- `src/` — Chapter files (ch01-design-decisions.md, etc.)
- `listings/` — Per-chapter code snapshots extracted from cuisineiq-rust at each chapter tag
- `code/cuisineiq-rust/` — Git submodule pointing to the public app repo
- `images/` — Figures and diagrams
- `t2t-book-plan.md` — Full book plan with progress table (read this for context on any chapter)
- `CHANGELOG.md` — What changed in each version
- `dogfood-gaps.md` — Tracked gaps in author-maintained and third-party tools (created by `/blocker`)
- `.github/workflows/` — CI builds HTML + PDF on every push; PDF attached to GitHub Releases on tag

## Toolchain

All Rust-based:
- `mdbook` — Book build system (`mdbook build`, `mdbook serve --open`, `mdbook test`)
- `mdbook-typst-pdf` — Print-quality PDF generation via the Typst typesetting engine (v0.7.3+, includes admonish support)
- `mdbook-admonish` — Admonitions plugin (TIP, NOTE, WARNING) — using fork until upstream merges PR #235
- `mdbook-quiz` — Interactive quizzes — using fork until upstream merges PR #62
- Future: callout preprocessor, EPUB backend

## Code inclusion

Code snippets use mdbook's `{{#include}}` directive with ANCHOR comments:

In the Rust source (in `listings/chXX/`):
```rust
// ANCHOR: grocery_item
pub struct GroceryItem {
    pub id: i64,
    pub name: String,
}
// ANCHOR_END: grocery_item
```

In the chapter Markdown:
````markdown
```rust
{{#include ../listings/ch03/src/models/grocery_item.rs:grocery_item}}
```
````

## Key conventions

- **Code snapshots, not live includes.** Each chapter's code is snapshotted from cuisineiq-rust at the chapter tag into `listings/chXX/`. This handles code that evolves across chapters.
- **No book references in public tool repos.** Never reference "Trunk to Table", chapter numbers, or CuisineIQ in public tool repos (panschema, playwright-rust, mdbook plugins). Public feature requests created by `/blocker` must stand on their own without book context.
- **Schema-driven development.** The CuisineIQ data model is defined in LinkML YAML and panschema generates Rust types, SQL migrations, and JSON Schema. Hand-written types that overlap with the schema are likely workarounds for missing panschema features.
- **Rust-only toolchain.** The book's thesis is that Rust is ready for full-stack development. The book toolchain itself should be Rust-based. When a tool is missing or broken, fork/fix/contribute rather than switching to a non-Rust alternative.
- **Versioning.** Tags follow semver: `v0.x.0` for new chapters or significant revisions, `v0.x.y` for small edits. `v1.0.0` is the complete first edition. Version numbers are sequential, not tied to chapter numbers. See `CHANGELOG.md`.

## Custom skills

### `/blocker [tool-name] <description>`
Log a dogfooding blocker in any tool — author-maintained or third-party. For author-maintained tools (panschema, playwright-rust, theoria, dokime): creates a public feature request and a tracking issue in t2t. For third-party tools (mdbook-admonish, mdbook-quiz, etc.): forks the upstream repo, sets up the contribution path (finish existing PRs or create new ones), configures the project to use the fork until upstream merges. Records in `dogfood-gaps.md`.

### `/resume [issue-number|repo-name]`
Check status of outstanding blockers and help pick up where you left off. Reads `dogfood-gaps.md`, checks if public issues are resolved, and shows resume instructions.

### `/audit-dogfood [chapter-number|file-path]`
Review cuisineiq-rust for invisible workarounds — hand-written types that should be generated by panschema, raw JS evaluation in E2E tests that should use native playwright-rust APIs, mdbook feature gaps worked around with raw HTML, etc. Run this before tagging a chapter boundary.

### `/pre-commit-review [file-path]`
Review manuscript text before committing. Checks for: (1) unattributed close paraphrasing of known sources (MinimumCD, Testing Goat, Rust Book, etc.) and (2) LLM-tell patterns that make prose sound generic (tripled parallel structure, inflating/minimizing language, grandiose closers, formulaic transitions). Run this before every manuscript commit.
